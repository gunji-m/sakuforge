# ADR 0006: 招待制をやめ、宣伝しない公開にする

ADR は「何をどう決めたか、理由は何か」を1件ずつ残す短い決定記録です。設計書ではなく、判断の履歴です。

- Status: Accepted
- Date: 2026-11-11
- Related: [ADR 0001](0001-declaration-and-origin.md)、[ADR 0002](0002-public-repository.md)、
  [ADR 0004](0004-vercel-nextjs-server-side.md)、[ADR 0005](0005-first-invitation-scope.md)、
  #54、#3、#19、#48

## 背景

[ADR 0001](0001-declaration-and-origin.md) の宣言と「利用者」の軸は、顔の見える少数を招待するとし、
[ADR 0004](0004-vercel-nextjs-server-side.md) はサーバー関数の1つを招待の確認に充てていました。

その後、利用者データを預からない形（ADR 0001 の「預かり方」）が固まり、サーバーには CSV も結果も
残らなくなりました。招待で守るものは「知らない人が使うこと」だけに縮みました。一方で、招待の仕組み
（合言葉の生成・保存・失効、cookie、CSRF、試行の制限）は、守るものに比べて重く、秘密情報そのものが
事故のもとになります。

本人は 2026-11-06 に招待制をやめると決め、2026-11-11 に「宣伝しない」の中身、宣言の読み替え、
Vercel の Hobby プランの条件を決めました。

## 決定

### 招待制をやめる

- 利用者を招待で限定しない。URL を知っていれば、誰でも使える
- 招待の確認（合言葉、cookie、CSRF、試行の制限）は作らない。サーバー関数は、CSV の検査と集計の1つだけになる
- 知らない人が使うことを受け入れる

### 宣言と「利用者」の軸の読み替え

ADR 0001 の宣言の1文目を読み替えます。2文目以降は変えません。

> 開発者以外の人にも、URL を知っていれば使える形で公開する。品質と安全を優先し、公開しても問題を
> 起こさないサービスにする。宣伝はしない。開発者自身が内部を理解できる大きさに保つ。
> 利用者データを預からない。

| 軸 | 決めたこと |
| --- | --- |
| 利用者 | 利用者を限定しない。URL を知っている人が使う。自分で登録できる仕組みとアカウントは作らない。宣伝はしない |

ほかの軸（目的、価値、制約、大きさ、預かり方）と価値の順番は、ADR 0001 のままです。

### 「宣伝しない」の中身

- SNS などで告知しない
- 検索エンジンに載せない（`noindex`）。設定は配備のときに行う

### 残すもの

- 宣伝しない
- 自分で登録する仕組みとアカウントを作らない
- 利用者データを預からない
- 公開しても問題を起こさない

### 条件

- Vercel の Hobby プランは非商用の利用に限られる。非商用、無課金、宣伝なしを守る間だけ Hobby プランで置く
  （ADR 0004 の「招待制、無課金、宣伝なし」の読み替え）
- 無料のあいだは、使用量を使い切って止まることを受け入れる（[設計](../design.md)の7節、#48）

### 東証データの利用範囲

- 銘柄マスターの利用範囲は、利用者を限定しない公開でも収まると、本人が判断した（#3）。個別回答の
  文面と内容は、ここにも書かない（[外部データとの約束](../external-data-policy.md)の4節）
- 銘柄マスター JSON をブラウザへ配らないこと、リポジトリに入れないことは変えない
- 銘柄マスター由来の情報を表示するときは、出典と基準日を表示する（[外部データとの約束](../external-data-policy.md)の3節）

### 理由

- **守るものが縮んだ**: サーバーに利用者データが残らないので、知らない人が使っても、ほかの利用者の
  データに届かない
- **秘密を持たない**: 合言葉を作らなければ、漏えい、失効、配り直しが起きない
- **大きさ**: サーバー関数が1つになり、cookie と CSRF の扱いを説明する必要が無くなる

## 検討した他の案

- **招待制を続ける。** 守るものが「知らない人が使うこと」だけなのに、合言葉の運用と実装が要る。採らない
- **Basic 認証などの軽い共有の合言葉にする。** 実装は軽いが、秘密を配って保つ運用は残る。採らない
- **検索エンジンに載せる。** 知らない人が検索から流れ込み、無料枠を使い切りやすくなる。宣伝しない
  という宣言とも合わない。採らない

## この決定で起きること

**良い面**

- 招待の実装、秘密情報、その運用が要らなくなる
- 使ってもらうときは、URL を伝えるだけで済む

**負担になる面**

- URL が広まると、知らない人が使う。要求が続いたときの守りは、基盤の対策と WAF のレート制限に任せ、
  それでも残る停止は受け入れる（[設計](../design.md)の7節）
- `noindex` を配備のときに設定し、効いていることを確かめる必要がある

**この決定では解消しないこと**

- `noindex` と WAF の具体的な設定（配備の Issue。#44）
- 銘柄マスター JSON の形と置き場（#66）

## 見直す条件

- 有料化するとき
- 実行環境に課金し始めるとき
- 利用者を限定する必要が出たとき
- 東証が月次 Excel の公開や利用条件を変えたとき（[外部データとの約束](../external-data-policy.md)の5節）
