# ADR 0003: 実装言語を TypeScript にする

ADR は「何をどう決めたか、理由は何か」を1件ずつ残す短い決定記録です。設計書ではなく、判断の履歴です。

- Status: Accepted
- Date: 2026-10-31
- Related: [ADR 0001](0001-declaration-and-origin.md)、#11

## 背景

[ADR 0001](0001-declaration-and-origin.md) の「作り方」は、検証と集計を純粋な関数として1言語で書き、
サーバーで動かすかブラウザで動かすかを後から変えられるようにすると決め、言語は ADR 0003 以降に
回しました。利用者データを預からないので、画面（UI）は必ず要り、検査と集計はブラウザでも動かせることが
条件になります。

本人は 2026-10-31 に、言語を TypeScript にすると決めました。

## 決定

検査と集計の純粋関数と UI を **TypeScript** で書きます。UI は React を想定し、構成は設計で決めます。

使う道具（10 進演算、入力検証、テスト、パッケージ管理、整形と lint）は、この ADR では決めず、
設計と [AGENTS.md](../../AGENTS.md) の規則に置きます。

### 理由

ADR 0001 の軸に照らして選びました。

- **大きさ**: 核と UI を1言語に揃えられる。2言語にすると、ビルド、テスト、依存の管理が2組になり、
  1時間で全体を説明できる大きさを保ちにくい
- **1人で説明できる**: 1人で作り、1人で運用する。読む言語と道具が1組で済む
- **配置を後から選べる**: 同じコードがブラウザでもサーバー（Node.js 等）でも動くので、純粋関数の配置を
  後から変えられる
- **経験**: 本人は tfdata-dashboard を React／TypeScript で書いており、UI の経験がある

### 比較

| 観点 | TypeScript | Rust（核）＋ wasm | Python（tfdata-api の継続） |
| --- | --- | --- | --- |
| 十進演算 | 標準に10進型が無く、依存か自作が要る | 依存（crate）で扱える | 標準の `decimal` で扱える |
| 文字コード CP932 | ブラウザと Node.js の `TextDecoder`（Shift_JIS）で decode できる見込み。差は実装時に確かめる | 依存（crate）で decode できる | 標準の codec で decode できる |
| 同一コード | ブラウザとサーバーで同じコードが動く | 核は wasm で両方に置けるが、UI は別言語 | ブラウザでは重い実行環境が要る |
| 保守 | 1言語・1組の道具 | 核と UI で2言語・2組の道具 | サーバーと UI で2言語 |
| 結果の突き合わせ | 合成データで tfdata-api の Python 実装と比べる | 同じ | 同じ言語で比べやすい |

## 検討した他の案

- **Rust で核を書き、wasm にしてブラウザで動かす。** 型と10進演算の扱いは核に向くが、UI は
  TypeScript になり2言語になる。学習を目的にしない今は、大きさの軸を優先する。採らない
- **Python で書く（tfdata-api の継続）。** 規則の参照元と同じ言語で突き合わせやすいが、ブラウザで動かすには
  重い実行環境が要り、UI は別言語になる。tfdata-api のコードは持ち込まない（ADR 0001）ので、同じ言語でも
  書き直しになり、言語を揃える利点は小さい。採らない

## この決定で起きること

**良い面**

- 核と UI を1言語で書け、ブラウザ側で検査する配置を選べる
- テスト、型、依存の管理が1組で済む

**負担になる面**

- 10進演算は標準に無いので、依存を採るか自作するかを決める必要がある
  （[入力を信用しない原則](../input-trust-principles.md)の「依存の採用基準」に従う）
- npm の依存は推移的に増えやすく、依存の数と更新を見張る負担がある
- tfdata-api の Python 実装とは言語が違うので、合成データで結果を突き合わせる手間が出る

**この決定では解消しないこと**

- 配置とフレームワーク（ADR 0004）
- 道具の選択と設計（設計の文書と AGENTS.md）
- CI、必須 check、`dependabot.yml`（言語確定後の別 Issue）

## 見直す条件

- 10進演算や CP932 の decode が、TypeScript では規則どおりに書けないと分かったとき
- 依存の数や更新の負担が、1人で保守できる範囲を超えたとき
- 学習を目的に含める、または核の性能が問題になるなど、Rust を採らなかった理由が変わったとき
