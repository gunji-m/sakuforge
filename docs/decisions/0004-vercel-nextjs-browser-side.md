# ADR 0004: Vercel と Next.js に置き、CSV の検査と集計はブラウザで行う

ADR は「何をどう決めたか、理由は何か」を1件ずつ残す短い決定記録です。設計書ではなく、判断の履歴です。

- Status: Accepted
- Date: 2026-10-31
- Related: [ADR 0001](0001-declaration-and-origin.md)、[ADR 0002](0002-public-repository.md)、
  ADR 0003（実装言語を TypeScript にする）、#10、#3

## 背景

[ADR 0001](0001-declaration-and-origin.md) は、検証と集計を純粋な関数として書き、サーバーで動かすか
ブラウザで動かすかを配置の選択として後から決めるとしました。ADR 0003 で言語を TypeScript に決めたので、
その関数をどこで動かし、画面をどこに置くかを決めます。

利用者データを預からないこと（ADR 0001 の「預かり方」）と、1人で作り1人で運用し費用を小さくすること
（同「制約」）が、配置を選ぶ主な条件です。

本人は 2026-10-31 に、配置を Vercel、フレームワークを Next.js（App Router）にすると決めました。

## 決定

- **核を分ける**: CSV の検査と17業種の集計の純粋関数は、Next.js に依存しない TypeScript のパッケージに
  置く。Next.js のアプリはそれを import するだけにする
- **ブラウザで検査する**: CSV の検査と集計は利用者のブラウザで実行し、CSV をサーバーへ送らない
- **サーバー関数は2つだけ**: 招待の確認と、銘柄マスター JSON の配布だけをサーバー関数に置く
- **置き場所**: Vercel。関数のリージョンは東京 `hnd1`
- **Next.js の使い方を絞る**: メジャーバージョンを固定する。Server Actions と高度なキャッシュの機能は使わない

### 条件

- Vercel の Hobby プランは非商用の利用に限られる。招待制、無課金、宣伝なし（ADR 0001 の宣言と軸）を
  守る間だけ Hobby プランで置く
- 銘柄マスター JSON をどこまで配ってよいかは #3 の結果に従う。関数で返すか静的に配信するかも、
  #3 の結果を受けて設計で決める

### 理由

- **預からない**: CSV がサーバーへ届かないので、保有明細を受け取る経路、ログ、保存先が初めから無い
- **大きさ**: サーバー側は2つの関数だけで、VPS、OS、Web サーバーの運用が要らない
- **配置を後から選べる**: 核が Next.js に依存しないので、サーバー側へ移すときも核は書き換えない
- **費用**: 少数招待の範囲では Hobby プランで足りる見込み

Next.js は、招待の確認と配布の関数を同じアプリに置けるので採ります。Server Actions とキャッシュの機能は、
どこで何が動くかを1時間で説明しにくくするので使いません。

## 検討した他の案

- **Vite と React の静的サイトにし、必要なときだけ Hono 等の小さな API を足す。** 仕組みは最も小さいが、
  招待の確認と配布の関数を別に置き、配備を2つ持つことになる。Next.js の機能を絞れば大きさは抑えられるので
  採らない
- **VPS に自前で配備する。** tfdata-api の形で、OS、Web サーバー、TLS、監視を1人で運用する負担が大きい。
  利用者データを預からない後継では、その負担に見合う理由が無い。採らない

## この決定で起きること

**良い面**

- CSV がサーバーへ届かず、預からないことを配置で守れる
- サーバーの運用がほぼ無くなる

**負担になる面**

- 検査は利用者の端末で動くので、上限値と検査時間の意味が変わる（設計の文書で洗い出す）
- 銘柄マスター JSON をブラウザへ渡すので、配布境界（#3）の結果に配置が縛られる
- Vercel と Next.js の変更に追従する手間がある。メジャーの固定で頻度を抑える

**この決定では解消しないこと**

- パッケージ構成と道具の選択（設計の文書と AGENTS.md）
- 招待の確認の具体（合言葉の扱い等）
- 銘柄マスター JSON の配布境界（#3）
- ブラウザ側の履歴（#4）

## 見直す条件

- サーバー側で検査する必要が出たとき（端末の資源で足りない、ブラウザに銘柄マスターを渡せない等）
- Vercel の料金、Hobby プランの条件、リージョンなどの条件が変わったとき
- 商用利用、課金、宣伝が要件になり、Hobby プランの条件を満たさなくなったとき
- Next.js のメジャー更新や機能の変化で、使い方を絞ったままでは保守できなくなったとき
