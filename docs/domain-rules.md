# ドメイン規則

この文書は、sakuforge が扱う保有 CSV、検査所見、構成計算の規則の正本です。言語や配置に依らない
「規則」だけを書きます。出自は gunji-m/tfdata-api の
`docs/api-design.md`、`docs/inspect-api.md`、`docs/test-data.md`、`app/schemas/inspect.py`、
`app/services/asset.py`（main `4a25bc93e8dba5b8bce866d6707bce6415ec61da`）です。逆算して書いた規則は
2026-11-01 に本人が確認して確定しました（#9、[ADR 0005](decisions/0005-first-invitation-scope.md)）。tfdata-api の
挙動は比較のための参照で、sakuforge の規則はこの文書が決めます。結果が tfdata-api と異なる点は
[10](#10-tfdata-api-との違い)に記録します。

検証と集計は純粋な関数として書きます（[ADR 0001](decisions/0001-declaration-and-origin.md)）。
[入力を信用しない原則](input-trust-principles.md)も併せて適用します。

## 1. 入力の上限

| 項目 | 規則 |
| --- | --- |
| サイズ | 10 MiB 以下。上限+1 byte までしか読まずに判定する。Vercel の関数の上限により、#20 の結果で見直す可能性がある |
| 文字コード | UTF-8（BOM 可）または CP932。この順に試す |
| データ行 | 非空データレコード 10,000 行以下 |
| 列 | 防御上限 100 列。対応 profile はヘッダー・データ行とも 22 列ちょうど |
| 検査時間 | 読み込み後 5 秒以内 |
| ファイル名 | 255 文字以下、パス区切りと Unicode 制御文字を含まない、`.csv` で終わる。日本語は可 |
| 種類 | `text/csv` または `application/vnd.ms-excel`。内容検証の代わりにしない |
| ファイル数 | 1件だけ。圧縮、複数、リモート URL は受け付けない |

データ行・列・時間の上限を超えたら、検査結果を返さずに処理上限として拒否します。走査を終えていない
結果を、完全な検査結果として扱わせないためです。

## 2. 国内現物保有 CSV v1（profile `domestic_cash_holdings_v1`）

最初の非空行がヘッダーで、次の22個と同じ順序で一致しなければなりません。

```text
銘柄,銘柄,銘柄,預り区分,保有株数,取得単価,現在値,現在値,評価損益,評価損益(%),買付金額,評価額,前日終値,前日比,前日比(%),評価額前日比,予想PER(倍),実績PBR(倍),予想配当利回り(%),予想EPS,実績BPS,予想1株配当
```

使う列は次の6つだけです（1始まり）。他の列は未使用ですが、配置の一部として検査します。

| 列 | ヘッダー | 用途 |
| --- | --- | --- |
| 1 | `銘柄`（1つ目） | 証券コード |
| 4 | `預り区分` | 預り区分 |
| 5 | `保有株数` | 保有株数 |
| 6 | `取得単価` | 取得単価 |
| 7 | `現在値`（1つ目） | 現在値 |
| 22 | `予想1株配当` | 予想1株配当 |

- ヘッダーセルは前後空白だけを除去して比較する。別名、大文字小文字変換、Unicode 互換文字の正規化はしない
- 列の追加・欠落・並べ替え、先頭の非空な説明行、未知の profile は拒否する。形式が変わったら推測で広げず、新しい profile を足す
- 空行は読み飛ばす。最初の非空行以外を見出しや説明行として読み飛ばさない。データ行は22列ちょうど

## 3. 値の規則

### 証券コード（列1）

- 4文字固定の TFD 標準証券コード: `^[1-9][0-9ACDFGHJKLMNPRSTUWXY][0-9][0-9ACDFGHJKLMNPRSTUWXY]$`
- 空白除去、大文字化、全角→半角、他の型からの暗黙の文字列化をしない
- 5桁の数値コードは取引所上は正当でも未対応。先頭4文字に切り詰めず `stock_code_unsupported` にする
- 形式が正しいコードだけを銘柄マスターと照合する（[5](#5-未知の証券コード)）

### 預り区分（列4）

前後空白を除去して 1〜32 文字。空値と制御文字は不正。

### 数値（保有株数・取得単価・現在値、列5〜7）

| 規則 | 内容 |
| --- | --- |
| 許す表記 | 符号なしの通常10進表記（`1234.5`）、または正しい3桁区切り（`1,234.5`）。カンマを含むセルは CSV 上で引用符で囲む |
| 空白 | セル外周の ASCII 空白だけ除去する。タブ、非 ASCII 空白、制御文字は不正 |
| 不正 | 欠損（空、`-`、`--`）、符号、指数表記、不正なカンマ、`NaN`、`Infinity`、負数 |
| 桁 | 非負の `NUMERIC(14,4)` 相当。整数部10桁・小数4桁以内、最大 `9999999999.9999` |
| 超過桁 | 小数5桁目以降が末尾ゼロだけ（`1.00000`）なら許す。有効数字があれば不正。値は10進で厳密に扱い、2進浮動小数点にしない |

### 予想1株配当（列22）

- 単一値、または ASCII `~` で区切った `下限 ~ 上限`。`~` の前後の ASCII 空白は任意。別の波線は不正
- 各端点は上の数値と同じ字句規則で、非負の `NUMERIC(10,4)` 相当（整数部6桁・小数4桁以内）。下限が上限を超えたら不正
- 単一値は下限だけを持ち、上限は無し。範囲は両端点を持つ。端点の選択や平均化はしない。等値範囲
  （`10 ~ 10`）も上限を持つので、単一値と区別できる

## 4. 行と識別子

- **行番号**: 1始まりの CSV レコード開始物理行。空行と引用符内の改行も数える。例: ヘッダーが1行目、
  正常なレコードが2〜3行目を占めるとき、次のレコードは4行目
- **行数**: 上限と `rows_scanned` は、物理行数ではなく非空データレコード数で数える
- **識別子**: 1つの CSV の中では `(証券コード, 預り区分)` が資産行の識別子。同じ証券コードでも預り区分が
  違えば別の行として持ち、株数や取得単価を合算・平均化しない。同じ組合せが2回目以降に現れたら
  `asset_key_duplicated`（後続の行に付ける）。同じ預り区分の中で買付ロットを分ける形式は未対応（必要なら別 profile）

## 5. 未知の証券コード

- CSV 構造と全証券コードの形式が正しい場合だけ照合する。形式不正や5桁未対応が1件でもあれば照合しない（「未実施」）
- 未知コードは重複を除いて文字列昇順で、全件返す。総数を併記する。無ければ空の一覧と総数 0
- 所見には位置なしの `stock_code_unknown` を1件だけ足す。severity は `warning` で、`valid` は false にしない。
  未知コードを行番号、数量、価格、利用者と結び付けない
- 未知コードの銘柄も CSV を拒否する理由にしない。その行は構成では「未分類」に入れ、評価額と年間配当見込みの
  合計にも含める

## 6. 検査所見

### 所見の形

| 項目 | 規則 |
| --- | --- |
| `code` | 64文字以下の安定した `lower_snake_case`（`^[a-z][a-z0-9_]*$`） |
| `severity` | `error` または `warning`。`error` だけが `valid` を false にする。`warning` は `stock_code_unknown` だけで、他の code はすべて `error` |
| `message` | 200文字以下の固定文言。元のヘッダー、セル値、ファイル名を埋め込まない |
| 位置 | 行（1始まり物理行）、列（1始まり）、field 名。ファイル全体の問題は位置なし。特定できない要素は空 |
| field 名 | `stock_code`、`custody_type`、`holding_count`、`purchase_price`、`current_price`、`dividend_per_share` だけ |

### code の一覧

| code | 位置 | 意味 | 固定 message |
| --- | --- | --- | --- |
| `csv_empty` | なし | 空または空行のみ | CSVファイルが空です。保有資産のCSVを選んでください。 |
| `csv_control_character` | なし／行 | NUL 等の禁止文字 | CSVに使用できない文字が含まれています。 |
| `csv_encoding_unsupported` | なし | decode できない | CSVの文字コードを読み取れません。UTF-8かShift_JISが必要です。 |
| `csv_structure_invalid` | なし／行 | CSV 構文の不正 | CSVの形式を読み取れません。引用符（"）の対応を確認してください。 |
| `csv_header_unsupported` | なし | ヘッダー・列順・profile の不一致 | 対応していない形式のCSVです。国内株式（現物）の保有資産CSVを選んでください。 |
| `csv_data_rows_empty` | なし | 検査できるデータ行が無い | 保有銘柄の行がありません。 |
| `csv_column_count_invalid` | 行 | 22列と不一致 | 列の数が見出しと合わない行があります。 |
| `stock_code_invalid` | 行・列・field | 証券コード形式の不正 | 証券コードを読み取れません。4文字の証券コードが必要です。 |
| `stock_code_unsupported` | 行・列・field | 5桁数値コード | 5桁の証券コードには、まだ対応していません。 |
| `custody_type_invalid` | 行・列・field | 預り区分の不正 | 預り区分を読み取れません。1〜32文字が必要です。 |
| `holding_count_invalid` | 行・列・field | 保有株数の不正 | 保有株数を読み取れません。0以上の数値が必要です。 |
| `purchase_price_invalid` | 行・列・field | 取得単価の不正 | 取得単価を読み取れません。0以上の数値が必要です。 |
| `current_price_invalid` | 行・列・field | 現在値の不正 | 現在値を読み取れません。0以上の数値が必要です。 |
| `dividend_per_share_invalid` | 行・列・field | 配当の単一値／範囲の不正 | 予想1株配当を読み取れません。数値か範囲（例: 40 ~ 50）が必要です。 |
| `asset_key_duplicated` | 後続の行 | 証券コードと預り区分の組合せの重複 | 同じ証券コードと預り区分の行が重複しています。 |
| `stock_code_unknown` | なし | 銘柄マスターに無いコードがある（warning） | 銘柄マスターに無い証券コードがあります。該当銘柄は「未分類」として集計しました。 |

### 並べ方と上限

- 1行に独立した問題が複数あれば複数返す。後続を安全に走査できない問題（ヘッダー、decode、構文）はファイル所見で止める
- レコード順、列順、code 順で安定して並べ、同じ code と位置の重複は除く。全件を数え、先頭200件だけを返す
- 検査結果は `valid`（error が 0 件のときだけ true）、profile、文字コード、件数（走査行数、error 数、
  warning 数、総数、返却数、省略の有無）、所見、照合結果を持ち、件数どうしが常に整合する

## 7. 17業種と33業種の構成

17業種と33業種は、同じ規則で別々に集計します。

| 項目 | 規則 |
| --- | --- |
| 評価額 | 行ごとに 保有株数 × 現在値（取り込み時点の値）。CSV の評価額の列は使わないので、端数が証券会社の表示と違うことがある |
| 分母 | 全行の評価額の合計。一部だけ（表示中のページなど）で計算しない |
| 計算不可 | 合計が 0 なら構成を計算せず「計算不可」とし、業種の一覧は空 |
| 分類 | 銘柄マスターの業種コードと名称（17業種、33業種）で集計する。銘柄マスターに無い銘柄と、業種が無い銘柄は「未分類」（コード無し）に集める |
| 構成比 | 業種ごとの評価額 ÷ 合計 × 100 を、小数第2位で四捨五入（half up）。文字列の10進表記で返す |
| 合計 | 100 に合わせる補正はしない（例: 87.66 と 12.35 で合計 100.01） |
| 並び | 構成比の降順。同率なら分類済みを先、未分類を後。分類済みどうしは業種コードを数値として昇順 |
| 一覧に出す業種 | 保有がある業種は、丸めて 0.00 になっても残す。保有の無い業種は出さない。小さい業種を「その他」にまとめない |

17業種コードは 1〜17（1 食品 … 17 不動産）、33業種は東証の33業種区分で、名称の組は東証の区分に従います。
構成を表示するときは、銘柄マスターの出典と基準日を表示します（[外部データとの約束](external-data-policy.md)）。

## 8. 年間配当見込み

| 項目 | 規則 |
| --- | --- |
| 行ごとの額 | 保有株数 × 予想1株配当。税引前 |
| 下限と上限 | 合計は常に下限と上限の2値で持つ。範囲（`下限 ~ 上限`）の行は下限と上限をそれぞれに足し、単一値の行は両方に同じ額を足す。範囲の行が無ければ下限と上限は等しい |
| 合算 | 全行を合算する。預り区分（NISA、旧NISA など）が違う同じ銘柄の行も区別しない。銘柄マスターに無い銘柄の行も含める |
| 上限 | 合計に上限は置かない。入力の桁（[3](#3-値の規則)）の制限だけで守る |
| 表記 | 文字列の10進表記で返す。2進浮動小数点にしない |

## 9. 確定の記録

2026-10-31〜11-01 に本人が確認して確定した規則（#9）:

- 構成比の丸め（小数第2位 half up）と、合計を 100 に補正しないこと
- 同率の並び（分類済みが先、業種コード昇順、未分類は最後）
- 構成比 0.00 の業種を一覧に残すこと
- 予想1株配当の桁（整数部6桁・小数4桁）
- 銘柄マスターに無い銘柄の扱い（[5](#5-未知の証券コード)、warning）
- 33業種の構成（[7](#7-17業種と33業種の構成)）と年間配当見込み（[8](#8-年間配当見込み)）
- 所見 code 16件と固定 message の文言（2026-11-01 に利用者向けの文言へ改めた）
- 未知コードの一覧を全件返すこと（[5](#5-未知の証券コード)）
- 入力の上限値。サイズは #20 で見直す可能性がある

## 10. tfdata-api との違い

後継のテストで tfdata-api の Python 実装と結果を突き合わせるとき、次は差として扱います。

| 項目 | tfdata-api | sakuforge |
| --- | --- | --- |
| 銘柄マスターに無い銘柄 | `stock_code_unknown` は error で、`valid` が false になる | warning で `valid` は true。その銘柄は「未分類」に入る |
| 未知コードの一覧 | 最大 50 件で、省略の有無を併記 | 全件 |
| 固定 message | 6節の文言と異なる（tfdata-api 由来の文言） | 6節の文言 |
| 33業種の構成 | 無い | 17業種と同じ規則で集計する |
| 年間配当見込み | 計算規則が無い | [8](#8-年間配当見込み)の規則で、下限と上限の2値を返す |
